# promptchek

Сервис, который превращает слабые промпты в рабочие: разбор по критериям, оценка 0-100 и переписанная версия.

## Стек

- Next.js 16 (App Router, Turbopack)
- React 19, TypeScript strict
- Tailwind CSS 4
- LLM — любой OpenAI-совместимый endpoint (OpenAI, OpenRouter, Groq, локальный vLLM/Ollama)

## Запуск

```bash
npm install
cp .env.example .env.local   # и вписать LLM_API_KEY
npm run dev
```

Открыть http://localhost:3000

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` | Базовый URL API, по умолчанию `https://api.openai.com/v1` |
| `LLM_API_KEY` | Ключ провайдера (обязателен) |
| `LLM_MODEL` | Модель, по умолчанию `gpt-4o-mini` |
| `FREE_MONTHLY_RUNS` | Лимит бесплатных прогонов (пока не подключён к квотам) |

## Структура

```
app/
  page.tsx              — лендинг + рабочий улучшатель
  api/improve/route.ts  — SSE-эндпоинт: скоринг → стрим LLM → скоринг
components/
  Improver.tsx          — клиентский экран
  ScoreCard.tsx         — карточка оценки
lib/
  scoring.ts            — гибридный скоринг (правила + веса по режимам)
  modes.ts              — режимы и инструкции для LLM
  llm/client.ts         — провайдер-агностик стриминг
  llm/prompts.ts        — системный промпт улучшателя
  rate-limit.ts         — in-memory лимит по IP
```

## Как работает скоринг

Детерминированные правила с весами: роль, контекст, формат вывода, ограничения, критерии качества, аудитория, примеры, структура, детализация. Для режимов `code`, `agent`, `system` добавляются свои критерии (стек, граничные случаи, тесты / инструменты, поведение при неоднозначности / правила отказа, тон, приоритет инструкций).

Правила дают воспроизводимость — один и тот же промпт всегда получает одну и ту же оценку.
